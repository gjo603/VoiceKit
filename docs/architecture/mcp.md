The optional FastMCP add-on: its tools, run outcomes, cancellation safety, macro source tools, and the writer internals that must stay single-sourced. The user-facing tool table and security model are in `mcp\README.md`.

**The MCP server** (`mcp\`, optional add-on — the repo's other Python besides `lib\split_pdf.py`) is a third automation path alongside the scaffolder and recorder: a FastMCP `server.py` exposing **create** tools (launch macros with a no-code `opens` mode, hotkey modules, snippets, workflows, AI actions + `update_ai_prompt`; plus `edit_hotkey_module` (2026-08-02) — an exact-match splice with file-Edit-tool semantics, because most fixes change one function and a full replace resends the whole body: old_string must match exactly once, the edited file is `/validate`d and rolled back on failure, undo is the same call with the strings swapped, and an isolated body's edit is live with NO master reload — the body runs fresh per press; and `update_hotkey_module` (2026-08-12) — the full-file counterpart: it rewrites VERBATIM exactly the file `read_hotkey_module` returns (the body, for an isolated module), where a `create_hotkey_module` replace would wrap the passed code in a fresh generated header — so read→tweak→update round-trips (saved as UTF-8+BOM with LF endings) and `read_hotkey_module(previous=True)`'s banked text restores its content with one call; same validate-with-byte-exact-rollback, the overwritten text banked in the same `logs\module-backups\` slot a create replace uses, quarantine un-parked on an in-process success, and an in-process module's new code must still define its registered `^!+<key>` combo (any modifier order) or the write is refused before touching disk — the in-process file IS the key binding, and dropping it would strand the hand-made Voice Access pairing), **inspect** tools (`list_automations` mirrors the home window's categories with exact voice phrases — and carries a long-running body's latest `status` line on its hotkey-module entry, see "Body status" above — plus `read_workflow`, `get_bridge_map`, `read_reference` (2026-08-03 — worked example code to copy, currently `web-scrape`: `templates\web-scrape-body.ahk`, a complete scraper body distilled from a real harvest of a few hundred listings — search term, keyboard walk, background-tab capture, dedupe file, resumable queue, varied pacing, Esc/`stop_module` stop. It is **not** a generator template — nothing fills it in — and it is served through the MCP rather than pointed at on disk because an MCP-only client has no filesystem access. It carries a *body's* `..\..\lib\` include paths, so `test_reference_bodies_are_readable_and_load` validates it by building a `hotkeys\bodies\` layout: a worked example that doesn't parse is worse than none), and the desktop-sensing pair `inspect_focus` / `dump_uia_tree` (2026-08-02): read-only UIA reports — the focused element with 3 levels of ancestry, and a window's tree as an indented type-plus-name outline — via the committed out-of-process probe `mcp\uia_probe.ahk` on `lib\UIA.ahk`'s walkers, writing to a temp FILE, never AutoHotkey's GUI-subsystem stdout; they exist because diagnosing "why does my find match nothing" used to cost a throwaway hotkey module and a bridge key, and because a FOCUSED element's accessible name routinely differs from the same element's copied-text form — `test_uia_probe_tree_reads_a_real_window` guards the report-format seam), and **trigger** tools — `run_automation` (launches any spoken automation's macro; `loop <name>` phrases launch `lib\LoopRunner.ahk` with the workflow base; refuses to relaunch a running Workflow Studio — `#SingleInstance Force` would discard unsaved recorded steps; optional `wait_seconds` to report the outcome; every launch runs with the **same working directory as its voice shortcut** — the macro's folder, `REPO_ROOT` for loops and batches — where it used to inherit the MCP server's; optional **`args`** (2026-09-30, WP5) are passed as an argv list, no shell, and echoed back as `args`: refused for Workflow Studio (its argument means load-file / `/record`) and for `loop <name>`, and for a **workflow** every argument must be an existing file or folder (full path, `%USERPROFILE%`/`%TEMP%` forms expanded) because `RunWorkflow` treats the stub's `A_Args` as the selection — `{{selected_file}}`/`{{selected_files}}` resolve to them and File Explorer is never consulted, so a selected-file workflow is testable on a fixture with no stub-format change. Raw scripts follow the documented convention `files := A_Args.Length ? A_Args : ExplorerSelectedFiles()` (with `#Include "%A_ScriptDir%\..\lib\ExplorerSel.ahk"`), stated in `create_launch_macro`'s description and the session instructions. There is deliberately **no generic dry-run**: VoiceKit can't know what 'dry' means for a raw script, and a flag a script ignores would be a false safety promise — a script may honour its own `/dry` argument. `test_run_automation_passes_args_and_cwd` pins argv, cwd, argv-as-selection end to end, and every refusal), `run_workflow_batch` (the "do X for each of these" tool: rows of label→value objects are validated against the workflow's inputs — its ask labels plus, since 2026-09-30, every `{{Name}}` a `fill` value uses that no step defines (`_input_labels`, mirroring `WfAskLabels`; so an invoice tab reaches fill steps with no `ask` step typing each value somewhere) — written to a per-run `logs\mcp-batch-<stamp>-<pid>.csv` (earlier ones are cleared) — Python `csv` module, utf-8-sig, same RFC-4180 dialect `WfCsvParse` reads — and `LoopRunner.ahk <Base> <batch>` runs them headlessly, one pass per row, Stop bar still up; collect values land in the sheet; or, with `source=` instead of `rows=`, from any CSV or Excel range — see "Batch from any CSV or Excel range" below. An all-blank row is refused, and so is ANY loop launch — this and `run_automation('loop X')` — while a loop of this tree is running (`_refuse_if_loop_running` names it): LoopRunner is `#SingleInstance Force`, so a retry used to cut the running batch short), `read_workflow_sheet` (parses `<Base>.inputs.csv` + `<Base>.results.csv` into columns/row-dicts so collected values flow back to the model — the read half of the batch round trip; it also carries **`last_run`** and gives an empty sheet **three distinct** notes — never ran / ran and failed / ran but collected nothing — because reporting all three as "No data yet" left the caller with nothing to act on), `press_hotkey` (synthesizes a bridge combo via a stdin-fed inline AHK script with `SendLevel 1`; validates the key is ONE character of the bridge pool (letters, digits and the measured-safe punctuation), refuses when the resident master isn't running (mid-reload it waits up to 6 s for the new master to report in and otherwise says VoiceKit is *restarting* — never "not running"; `health()` carries `master_restarting` for the same window, via `_master_restarting`), and can only press combos registered in `bridge-map.txt`, never arbitrary keys; a companion resolves by the automation name `list_automations` folds it under), `list_running` / `stop_module` / `read_module_status` (2026-08-03 — the process-lifecycle trio; see "Body status" above for the stop-flag convention. `read_module_status` **joins the status line to the liveness check** for one module, because either half alone misleads: a fresh-looking line from a body that died hours ago reads as progress, and a running body with no line reads as nothing happening — it names which of the four states you are in), and `run_ahk_snippet` (2026-08-03) — one-off AHK v2 in a throwaway process, the anti-Tab-Probe: a 25-second diagnostic used to cost a bridge key, registry lines and a delete afterwards, now it costs nothing. The snippet gets `lib\_Common.ahk` + `lib\Browser.ahk` (which pulls in `UIA.ahk`) + `lib\ExplorerSel.ahk` (2026-09-30 — `ExplorerSelectedFiles`, so a probe of the selection needs no include; its names are in the taken-names scope, `Explorer*`, and clash with nothing pre-included) pre-included and a predefined `Out(value)` that reports through a temp FILE (never GUI-subsystem stdout); a trailing `ExitApp` keeps "runs once" true even if the code declares hotkeys/GUIs; cwd is the temp folder so relative writes vanish with it; a timeout kills the process — since 2026-10-01 with everything it started, see "Processes" below — but still returns what `Out()` wrote — the partial log is the diagnostic. **Snippet errors surface instead of vanishing** (2026-08-03 feedback): an uncaught runtime error in a GUI-subsystem process pops a MODAL dialog — `/ErrorStdOut` covers load errors only (measured) — so a bad snippet used to sit the whole timeout and report nothing. The generated prelude now registers `OnError`: the process exits **3** immediately with `UNCAUGHT <type>: <message> — snippet line N` (numbered in the snippet's own lines; prelude length subtracted) written to both the Out-file (in sequence with the snippet's own output) and `errors`; a load error exits **2** with its `(NN)` re-numbered to the snippet line, anchored to the filename so digits in the code excerpt are never touched. `Out()` also serializes objects/arrays/Maps (one level, alphabetical OwnProps order) instead of throwing — `Out(UiaRect(el))` was the exact crash that fed the silent-death hole. `test_run_ahk_snippet_surfaces_uncaught_errors` + `test_run_ahk_snippet_out_serializes_objects` pin all of it. Delete parity guards: dynamic code-block snippets are refused (line-delete would orphan the block and brick the master on reload — same rule as Home) with validate+rollback on the rewrite; workflow/hotkey deletes raise on nonexistent names and cross-guard same-named non-workflow macros; `hotkey_module` refuses the reserved `Snippets` before touching anything; names resolve to the REAL on-disk stem (`_resolve_existing_base` — `clean_phrase('WebScrapeDemo')` is `Webscrapedemo`, which on case-insensitive NTFS still deleted the file while case-sensitive line matchers left a dangling `#Include` that refused every reload) and `_index.ahk` / `bridge-map.txt` lines match caselessly on the exact field (`_include_targets` / `_map_line_targets`; leading-underscore stems like `_index` stay unreachable); workflow/ai_action/launch_macro deletes also retire a companion hotkey (`_remove_companion_hotkey`) and `list_automations` folds companions into their automation's `hotkey` field, never listing `*.hotkey.ahk` as modules (see the companion-hotkeys paragraph above). **Never report a run's success from its exit code** (2026-08-01) — `_attach_outcome` in `voicekit_writer.py` reads `logs\workflow-runs.ini` and puts `ok` / `outcome` / `failed_step` / `step` / `reason` / `passes_done` / `passes_total` plus a step **`trace`** (the tail of `workflow-runs.log` from the last run's start marker) on `run_workflow_batch` and on `run_automation` when the target is a workflow. A failed `capture` step (2026-09-30) reaches this report as `reason: "Command exited with code N."` and nothing more — the engine never records stderr or the filled-in command, so a client file named in a traceback or in `{{selected_file}}` can't ride out in a response (the stderr tail is shown only in the local popup). `WorkflowStep` maps `capture` from `label` + `command` + `seconds`. A `since` stamp taken just before `Popen` discards a record left by an *earlier* run — a stale outcome reported as this one's is worse than no outcome at all. Exit codes are only the fallback, and only for `LoopRunner.ahk` launches (`exit_codes=True`); a generated workflow stub always exits 0, so its code means nothing. `mcp\_conformance\runrecord.ahk` + `test_run_record_reads_back_what_the_engine_wrote` guard this AHK-writes/Python-reads seam — `IniWrite` produces UTF-16LE with a BOM, which only a real round trip catches.

**A cancelled request must never kill the connection** (2026-08-03, from a real session): the client cancelled a slow `dump_uia_tree` after ~3.4 s and discarded the message id; the mcp SDK's `RequestResponder.cancel()` then sent an error reply ("Request cancelled") for that id, the client took the orphaned reply as a protocol fault, closed the stdio pipes, and **every later call returned -32000 for the rest of the session** — the writer being importable directly was the only thing that saved the run. The spec sides with the client (after a cancellation the receiver SHOULD NOT respond), so `server.py`'s `_install_quiet_cancel()` patches `RequestResponder.cancel` to cancel the work, mark the request completed, and write **nothing** — and `RequestResponder.respond` to drop the reply of a request the client cancelled (2026-09-30: a sync tool's worker thread can't be interrupted, so the handler can return from it and reach `respond()` with no checkpoint in between, after `cancel()` marked the request done; stock `respond()` then asserted "Request already responded to" into the server's task group — the wire test's one flake, a real race, pinned deterministically by `test_quiet_cancel_survives_a_late_respond`; the wire test also fails on any server traceback now). Version-guarded against SDK drift (verified on mcp 1.28.1; unknown internals fall back to stock behavior), and pinned ON THE WIRE by `test_mcp_cancellation_is_not_connection_fatal`, which drives the real server over real pipes: initialize → slow `tools/call` → `notifications/cancelled` → asserts no reply for that id ever arrives (the window outlives the abandoned worker, catching a late reply too) → asserts `tools/list` still answers on the same pipes. The test skips itself politely when `fastmcp` isn't installed — the MCP is an optional add-on and the AHK-only install must stay green. What this cannot fix: a client that tears down anyway, or restarting the server inside a live client session — both are client-side; the mitigation is that the trigger is gone and `voicekit_writer` remains importable as the fallback surface.

**Macro source is readable, patchable, and honestly labeled** (2026-08-05, from the Split Pages debugging run — a session that diagnosed a race the tooling made invisible, at the cost of a human pasting 250 lines into chat and hand-applying the fix). Four MCP additions, all in `voicekit_writer.py` + `server.py`, pinned by `test_macro_source_read_update_edit_and_kinds` / `test_read_log_tails_and_filters` / `test_near_miss_errors_name_what_the_name_is`: (1) **`read_macro_source(name, previous=False)`** returns any `macros\` script's full source plus its `kind` (`raw_script` / `opens` / `ai_action` / `workflow_stub` / `tool`) and header-comment `description`; **`update_macro`** is the write half — full replace, `/validate`d with byte-exact rollback, the overwritten source banked one step deep in `logs\macro-backups\<Base>.prev.ahk` (hash + first lines in the response, `previous=True` reads it back, delete removes it — the exact `module-backups` pattern) — and **`edit_macro`** is the patch-shaped splice (shared `_splice_once` core with `edit_hotkey_module`, same exactly-once/rollback/swap-to-undo semantics). Both refuse builtins and generated workflow stubs (a stub edit would be silently regenerated away — the guard says so and points at `create_workflow`). (2) **`read_log(log, tail, filter)`** — `activity` (`created.log`), `errors` (`errors.log`), `runs` (`workflow-runs.log`); filter is applied BEFORE the tail so a tool's last N runs survive unrelated traffic; a missing file is an answer, not an error. This is what turns "it keeps crashing" from an interview into one call — Split Pages had been logging `saved of pageCount` all along, and died-at-page-7-then-12-then-4 is the varying-failure-point signature of a race, visible before reading any code. The write side is `_Common.ahk`'s new uncaught-error capture (see the `_Common` paragraph). (3) `list_automations` launch-macro entries carry an explicit **`kind`** — `opens` vs **`raw_script`**, which also surfaces the script's leading banner comment as `description` (`_macro_description`: borders dropped, `;` stripped, capped) — a full interactive application used to be distinguishable from a one-line opener only by a MISSING field. (4) **Near-miss errors**: every not-found path (`read_workflow`, `run_workflow_batch`, `read_workflow_sheet`, `read_ai_prompt`, `read_hotkey_module`, `read_module_status`, `edit_hotkey_module`, `run_automation`, the macro tools) appends `_near_miss(base)` — what the name DOES exist as and which tool reads it ("looked for SplitPages.steps.txt" now continues "…exists as a hand-written script — read_macro_source returns its source"). The index always knew; the errors just never asked it.

**Writer internals that must stay single-sourced** (2026-09-30 cleanup): (1) every write-then-load-check goes through **`_write_validated` / `_replace_validated`** — `_FileSnapshot` keeps the exact previous bytes, and ANY failure (a failed check, or the check itself raising) puts them back or removes a new file; banked backups (`_bank_previous`, both `module-backups` and `macro-backups`) are the raw previous bytes, with the public `previous_body_*` / `previous_source_*` keys unchanged. `create_workflow` replacing a workflow restores the old steps + stub instead of deleting them. (2) **`reload_voicekit()` returns `'reloaded' | 'not_running' | 'refused'`**; `_reload_outcome(subject)` adds `reloaded` / `reload_status` / `reload_note` (one wording, `_reload_note`) to every tool that reloads, and tools whose result never depends on a reload (launch macros, workflows, AI actions, isolated body edits/updates) return no `reloaded` key but a "nothing needs reloading" note. (3) The reload records what its preflight parked in **`_LAST_PARKED`**: an in-process module (or `Snippets.ahk`) that loads alone but clashes inside the master is rolled back — new: file + its registry lines removed; replaced: previous bytes back, switched back on, reloaded again (and if that reload parks the restored version too, the error says it's off) — and the call raises with the load error (`_undo_if_parked`); other modules the same reload parked are named in the note. **Back-to-back reloads wait for the previous `VoiceKitLauncher.ahk`** (`_LAST_LAUNCH`, bounded by `LAUNCHER_WAIT_S`) so two preflights never edit `_index.ahk` at once, and the launcher says `#SingleInstance Off` (the v2 default, Prompt, left a second launcher on a modal). Tools that reload hold `_RELOAD_LOCK` (`@_serialized`) for the whole write-reload-check, because FastMCP runs sync tools on a thread pool. (4) Liveness: `voicekit_running()` answers from `master-status.ini`'s pid + heartbeat via kernel32 (`_master_alive`, ~1 ms) and only falls back to the process scan when that is ambiguous (no file, a live pid with a stale heartbeat, or a dead pid whose heartbeat is still fresh without a clean exit — a reload mid-handover); `_ahk_processes()` is the ONE Win32_Process query (loops, bodies, the Studio guard filter it in Python); `stop_module` waits on process handles (`WaitForMultipleObjects`) and `TerminateProcess`es instead of polling PowerShell (a pid it can't open is polled for the grace period and reported, not assumed gone; one that refuses even a look — ACCESS_DENIED on every open — is checked by the process scan; any such pid is listed in `could_not_open`, and a stop involving one is never called `graceful` — if it vanished, `how` is `exited`, because whether it saw the flag can't be told; nothing is waited on after a force-kill that ended nothing). (5) `_macro_info(base)` → `(path, text, kind)` is the one macro classifier (listing, near-miss errors, update/edit guards, `create_workflow`'s overwrite guard — which also refuses a builtin tool name — and the delete cross-guards); `_require_module` is the one "existing module" check; `_read_text_any` is the only text reader; artifact paths are functions (`_macro_file` etc.) because tests retarget `REPO_ROOT`. Split Pages is **delete-protected but editable** (`_DELETE_PROTECTED_LOWER`; the Home window's side is a separate change). Tests: `_sandbox()` in `test_conformance.py` retargets `REPO_ROOT` **and** `VOICE_MACROS` (and the module points `VOICE_MACROS` away from the real Start Menu for the whole run).

**Written for an agent** (2026-09-30, WP1/WP9/WP10 of `docs\roadmap-extraction.md`, from the document-extraction feedback — the session ran on a second PC's *installed* copy, so everything here works from an install root, not only the repo):

- **Load errors explain name clashes.** AutoHotkey v2 keeps functions, classes and variables in one case-insensitive namespace, so a top-level `LOG := ...` fails with *"This Func cannot be used as an output variable. Specifically: LOG"* — and `Log` is an AutoHotkey **built-in** (reproduced with no include at all; `_Common.ahk` also redefines it), so a VK_ prefix on our names would not have prevented the reported clash (the user decided: explain and list, no rename). `_explain_ahk_error(text, code=None, script=None, prelude_lines=0)` appends one `Hint:` line after the raw error for the three measured forms — *output variable* (a variable, a `global` declaration, a loop/for variable), *function/class declaration conflicts with an existing Func/Class* — naming the owner: "an AutoHotkey built-in function/class" (the curated `AHK_BUILTINS`, which the test checks name by name against the installed interpreter; an unlisted name is confirmed by a one-line `/validate` probe), "a VoiceKit function defined in lib\_Common.ahk line N, which this code includes" (an index of **definitions only** — column-0 `Name(...) {`/`=>` and `class` — over the failing script's `#Include` chain, `%A_ScriptDir%` / `%A_LineFile%` resolved and nested, so Browser.ahk → UIA.ahk/Clip.ahk counts; the lib/master index is the fallback for a clash inside the resident master), "the Out() helper run_ahk_snippet predefines", or the user's own earlier definition (a declaration conflict skips the definition the error sits on). It also flags a v1-style doubled quote on the failing line (`a""b`, or three quotes in a row) with the `` `" `` rule, and — for `run_ahk_snippet` only — the two runtime shapes (`Expected a Number but got a Func` → the name on that line is a function; `has no method named "Call"` → a parameter/local hides the function, the `Max`/`max` trap). Applied at the user-facing raise sites only: `_write_validated` (every create/update/edit of macros, modules, bodies, AI actions and workflow stubs — explained *before* the rollback removes the file), `create_snippet`, `_clash_error`, and `run_ahk_snippet` (exit 2 and exit 3), **never inside `validate_ahk`**, whose text `master_preflight` truncates and `_error_module` parses — the hint goes at the end so the first `file.ahk (N)` is still AutoHotkey's. `run_ahk_snippet` also replaces its throwaway script's full temp path with `snippet.ahk`, and its prelude says `#Warn All, Off`: v2's load-time warnings (VarUnset, Unreachable) are modal MsgBoxes, so `Out(zz)` or a trailing `return` used to sit the whole timeout with empty output and errors — an unset read now throws at run time and exits 3 naming the variable.
- **Session instructions.** `FastMCP(instructions=vk.server_instructions(), version=vk.VERSION)` (version only when the SDK takes it). One block per session, not per tool: what each kind of code gets pre-included, the taken names — generated at start from the libraries (`_taken_names`: the shortest non-family names in the snippet scope, capped, plus the fixed families `Uia*`/`UIA_*`/`Browser*`/`Body*`/`Hotkey*`/`Bridge*`/`Master*`/`Wf*` and any first word three or more definitions share) and `COMMON_BUILTIN_CLASHES` — the quote rule, "edit/update, don't recreate", the path tokens (`check_path`, scoped `unmask=[...]`), one line each for `run_process` + the `max_wait_s()` cap + `background=True`/`read_job`, `run_automation(test=True)` + `VkResult`, and `list_processes` (2026-10-01), and the tool-name prefix rule + "call server_info". It loads every session, so `test_instructions_names_exist` holds it under 4000 characters. `test_instructions_names_exist` proves every listed name is a real definition or a built-in on the interpreter, and that the server passes exactly this text.
- **Server identity.** Root `VERSION` (`1.2.0` in the repo; `build\Build-Installer.ps1` writes `<base>+<short hash>[.dirty].<yyyyMMdd>` into the staged copy, since an install has no `.git`; a checkout's unstamped version gets `+<hash>` from git at import). `health()` — on every response — gains `version`, `install_root` and `server_stale` (server.py / voicekit_writer.py mtime differs from the stamp taken at import → a "restart the MCP server / reconnect" note). **`server_info()`** (read-only tool): version, install root, python, AHK path, pid + start time, stale flag, every running VoiceKit `server.py` process (one CIM query; a venv launcher and its child interpreter fold into one entry; `this_server` marks ours; a `server.py` counts when `voicekit_writer.py` sits beside it or the command says voicekit), and every client registration (`~/.claude.json` top-level and per-project `mcpServers`, `%APPDATA%\Claude\claude_desktop_config.json`, the install's `.mcp.json`) with command + args and `this_install` — **never `env`**, which can hold secrets. On this machine VoiceKit is registered in both Claude Code and Claude Desktop, each running its own server — the likely source of "two sets of tool names". **2026-10-01 (feedback #4: tool names moved from `mcp__claude-device__lcl-voicekit-*` to `mcp__remote-devices__voicekit__*` mid-session, and server_info said "registered 3 times" with two server processes):** `connected_client` is the MCP `clientInfo` (`name`, `version`, `title` when sent) of the session asking — read by `server._connected_client()` from the FastMCP context (`request_context.session.client_params`; the writer takes it as a plain dict and never imports fastmcp; `None` outside a request); `same_client_duplicates` (`_same_client_duplicates`) lists only the places where ONE client loads two VoiceKit entries — Claude Desktop: every entry; Claude Code: user scope everywhere, `projects[P]` in P, `.mcp.json` in this repo (same folder, any spelling, is one place), and a same-named narrower entry REPLACES the wider one, so names count caselessly per place — and the note names them as the real problem while entries in different clients are called normal; when the connected client is the one with the duplicate it says so, and a client whose config isn't read here (a bridge, a remote device link) is said to be one. `tool_name_prefixes` (`TOOL_PREFIX_NOTE`, also one line of the session instructions): the `mcp__<server>__` prefix is assigned by the client or a bridge and can change on a reconnect through a different path; the names after it are stable — re-list and retry. VoiceKit cannot rename what a client shows. Tests: `test_server_info_registrations_by_client`, `test_server_info_names_the_connected_client_on_the_wire`.
- **Paths normalized (WP9 phase 1, always on).** `server._guard` runs every dict result and every ToolError message through `vk.normalize_paths`: the temp dir then the profile (most specific first; both slash styles, the doubled-backslash spelling, long and 8.3 forms, caseless, path-boundary anchored so `C:\Users\bob` never eats `C:\Users\bobby`) become `%TEMP%` / `%USERPROFILE%`. Exempt, byte-for-byte: `NORMALIZE_EXEMPT` — `read_macro_source.source`, `read_hotkey_module.body`, `read_workflow.steps`, `read_ai_prompt.prompt`, `read_reference.code`, `update_ai_prompt.previous_prompt` (authored text a caller sends back — the last is the prompt's undo). The inverse, `expand_user_paths`, runs on the path-taking inputs (`create_launch_macro(opens=)`, a workflow `run` target and `focus` launch command, and `run_workflow_batch` row values and `source` path — never the cells read FROM a source, which are the user's own text — `read_workflow_sheet` rows come back normalized, and a row handed back as shown must type the real path), so an agent can pass back what it was shown. Phase 2 (masking) is below.

**Privacy masking** (2026-09-30, WP9 phase 2 of `docs\roadmap-extraction.md`, for an office that handles client documents, whose client names ARE its file and folder names — `Documents\Clients\Smith John\2025 Invoice Smith.pdf` — and whose MCP results go to a cloud model). `mcp\privacy.py`, applied in ONE place: `server._guard` → `_protect` → `privacy.protect(result, root, normalize=vk.normalize_paths_text, exempt=NORMALIZE_EXEMPT[tool], unmask)`, over EVERY result whatever its type (a list or string used to skip it) and every error message (`_protect_error`) — including exceptions outside the writer's own error types, which `_guard` now catches and re-raises masked (FastMCP's stock error text would carry `str(e)` unmasked, e.g. a `KeyError` holding a path). User decisions, all built as decided:
- **Modes** — `logs\settings.ini [Privacy] Mode=paths|strict|off`, **`paths` when absent** (masking on by default); an unknown value falls back to `paths` with a note on `voicekit.note`. `MaskRoots=` adds `;`-separated roots outside the profile (a drive folder, a UNC client share; `%USERPROFILE%`/`%TEMP%`/env vars expand; a relative entry is ignored with a note). `AllowBlanketUnmask=1` (also true/yes/on) is the only thing that lets a blanket `unmask=True` through — absent or anything else = refused. Read per call through an mtime+size cache (`privacy.settings`), UTF-16 (AHK `IniWrite`) or UTF-8, section/key caseless. **No tool can change it** — not a parameter anywhere; Home / AI Settings don't touch it. The mode rides on every response as `voicekit.privacy`.
- **paths** — after phase 1, every segment under `%USERPROFILE%`, `%TEMP%` (itself under the profile) and each MaskRoot becomes `<dir#hex>` or `<file#hex>` + the kept extension (1–8 alnum chars with a letter; a folder never keeps one). **Readable** (`_Ctx.readable`): anything equal to, inside, or an ANCESTOR of a readable tree — the VoiceKit root (so an install at `%LOCALAPPDATA%\Programs\VoiceKit` and every path leading to it stay readable), `sys.prefix`/`base_prefix`/the interpreter's folder, `VOICEKIT_AHK`'s folder, and profile-relative `AppData\Local\Programs\Python`, `AppData\Roaming\Python`, `AppData\Local\Microsoft\WindowsApps`, the `Voice Macros` / `Startup` / `AutoHotkey` Start Menu folders, `AppData\Roaming\Claude`, `.claude`, `.claude.json`; then (after the MaskRoot check) the known folder NAMES at their own level only (`_READABLE_LEVELS`: Desktop, Documents, Downloads, Pictures, Videos, Music, … `OneDrive` / `OneDrive - <org>` and their Desktop/Documents/…, `AppData`, `AppData\Local|Roaming|LocalLow`, `AppData\Local\Temp|Programs|Microsoft|Packages`, the Start Menu chain), and under `%TEMP%` the NAMES of `run_process`'s job folders only (`_TEMP_READABLE`: `VoiceKit\jobs\<job id>` and its `stdout.txt` / `stderr.txt` / `meta.json` / `exit.json` — a job id masked as `<dir#..>`, and then bare-masked in the `job_id` field itself, made `read_job` / `stop_job` unusable over MCP; anything else a job writes in its folder, its default cwd, stays masked). **Decided: VoiceKit's own file names stay readable** — macro/workflow/module names are the user's automation names, not client data, and an agent can't work without them (so: don't name an automation after a client; the README says so). Everything else under the profile is masked, including `%TEMP%` contents.
- **Where a path ends** — segments may hold spaces, so the anchor regex takes separator-delimited runs of legal filename characters (plus tokens, minus `%` so two paths in one line never merge). The LAST segment can run into prose ("…\Invoice.pdf to disk"): when its folder exists, the folder's listing (`os.listdir`, cached per response, never on a UNC path) picks the longest real entry followed by a boundary character; otherwise a closing quote (`'` then space/punctuation/end) ends it, then the LAST extension followed by a boundary, then trailing punctuation. The listing is trusted only when what follows reads as prose: a message may name a file that ISN'T there (moved, never made) beside a sibling that merely starts the same — `Smith` beside the text `Smith Jane.pdf` — and cutting at the sibling would leave ` Jane.pdf` in the clear. So the longer reading wins when it ends in an extension, when the path was closed by `"` (the whole segment is the name), or when the next word starts with a capital or a digit. Segments also take URL `%XX` escapes (a `file:///…/Smith%20John/…` URL, whose decoded name then gets the bare-name pass too). Anchors besides `%USERPROFILE%`/`%TEMP%`: `%APPDATA%`, `%LOCALAPPDATA%`, `%OneDrive%` (and its Commercial/Consumer forms) when they sit inside the profile, and `~\` starting a word; the `%VAR%` anchors match mid-word too (phase 1 does), a MaskRoot only on a boundary. **Redirected shell folders** (Desktop/Documents/Downloads/Pictures/Videos/Music from HKCU `User Shell Folders`, read once per process) that live OUTSIDE the profile — folder redirection to a server share is common on an office domain — are masked like implicit MaskRoots. A readable tree that would CONTAIN the profile or temp (an interpreter or `VOICEKIT_AHK` sitting directly in the profile) is ignored, or it would unmask everything. Over-masking is the failure direction on purpose — any tokenization round-trips because a token maps to the exact text it replaced.
- **Tokens** — HMAC-SHA256 of the case-folded name under a per-install random key, `logs\privacy.key` (32 bytes hex, created with `O_EXCL` on FIRST USE — a response with nothing to mask writes no key and no map), 6 hex chars growing to 12 only on a collision (6, not 4: with a few thousand client files a 4-hex collision is near certain, and a collision is what could ever make a stale token mean a different name). The map `logs\privacy-tokens.json` (`hex → {t: name, p: [first parent, normalized], s: epoch}`, capped at 20 000 names, newest kept) is written temp-file + `os.replace`, under a cross-process `O_EXCL` lock file with merge-on-write (two registrations = two server processes), so one token can never be handed out for two names. Ids dropped by the cap are **retired** (kept in the map's `retired` list, capped at 100 000) and never reissued — an agent may still hold one, and reissuing it would expand it to a different file; a retired id reads as unknown. A map file that exists but won't read (locked past the retries, truncated, hand-edited) is **never replaced by an empty one** — that would silently reset every id; `_assign` refuses (so the response fails closed) until it reads again or is moved aside. **Expansion is verified**: `_lookup` recomputes the HMAC of the stored name and refuses a token it doesn't start — a corrupted or edited map can never expand a token to somebody else's file.
- **Bare-name pass** — every name masked in a response is then masked where it appears on its own in the same response's strings (not dict keys): whole-word, caseless, longest first, the file name with and without its extension; tokens and `%VAR%`s are protected; names shorter than 3 characters, without a letter, or equal to a known folder word are skipped. Names this call **expanded from tokens in its input** (`privacy.start_call`/`take_expanded`, per thread, around the writer call in `_guard`) get the same pass — a script handed `<file#..>.pdf` that echoes just the file name must not send it straight back. It is a dict lookup per candidate word start (3-char prefix → the few name lengths to try), not a regex alternation: Python's `re` tries an N-name alternation at every position, and a log with thousands of masked names sharing a prefix (`2025 …`, `Client 0001 …`) took seconds (measured 3 s → 0.3 s for 5 000 paths in one 400 KB string). **Limits, documented**: a client name that never appears as part of a masked path in that response (a window title, a form field, a sheet cell) is not caught; nor is a path split across lines (the part after the line break is prose to the scanner).
- **strict** = paths + `<ssn#hex6>` for `\d{3}-\d{2}-\d{4}`, `<ein#hex6>` for `\d{2}-\d{7}` (neither inside a longer digit/dash run, so dates, phones, `12-3456`, `123-45-67890` pass), and nine bare digits (optionally `3 2 4` spaced) ONLY right after an SSN / ITIN / TIN / EIN / FEIN / Social Security / Tax(payer) ID label — an unlabelled nine-digit number is far more often an invoice or account. HMAC'd with a kind salt for correlation, **never stored** — `reveal` and every input path refuse them as one-way.

**Batch from any CSV or Excel range** (2026-09-30, WP7 of `docs\roadmap-extraction.md`, from the extraction feedback: a *Send Amount* workflow was walking an Excel sheet with hard-coded arrow keys). `run_workflow_batch` takes exactly one of `rows` (unchanged, byte-for-byte the same batch file) or **`source`** — a `.csv`/`.tsv`/`.txt` or `.xlsx`/`.xlsm` path (`expand_user_paths` applies) — with `sheet`, `cell_range` (`A2:C40`, open-ended `A2:C`, `A:C`, optionally `Sheet!`-prefixed), `header` (the range's first row is the header), `columns` (label → header name caseless / `col:C` / column number, A = 1; unmapped labels match a same-named header — the `WfLoopCsvRows` identity rule), `require` (labels that must be filled), `skip_if_filled` (done-mark columns), `skip_blank` (all MAPPED cells blank — an unmapped note column doesn't count, which is exactly the case `WfLoopCsvRows` alone would have run), `date_format`, `dry_run` and `preview_rows`. Design points:
- **Python only; no AHK or format change.** Any source is normalized into the same per-run `logs\mcp-batch-<stamp>-<pid>.csv` LoopRunner already reads, with one extra column, `VoiceKit source row` (`BATCH_META_COLUMN`; a label of that name is refused). `WfLoopCsvRows` ignores the column but it keeps every record non-blank, so **pass N is always the Nth row written** and the row names its source row. All skipping is Python's. `mcp\_conformance\batchrows.ahk` runs the real `WfLoopCsvRows` over a written file (commas, quotes, newlines, unicode, `00123`, dates, a kept all-blank row).
- **Reading.** CSV: UTF-16 by BOM, else UTF-8 (BOM or not), else cp1252 — Excel's plain "CSV (Comma delimited)" (a byte cp1252 leaves undefined is refused, never typed as a replacement character); the delimiter is decided by the first line holding any of tab / comma / `;` (title lines with none are skipped): tab if it has one (or `.tsv`), else comma, else `;` (European Excel). Row numbers are CSV **record** numbers (a quoted newline doesn't start one) — the same numbering `WfLoopCsvRows`' `srcRec` uses. xlsx: openpyxl, **imported lazily** (a CSV never needs it; without it an xlsx gets "pip install openpyxl into mcp\.venv"), `read_only=True, data_only=True` (cached formula results). An open-ended range is trimmed to the last row / column holding something, and reads past the sheet's recorded `<dimension>` (`reset_dimensions` — some writers record just `A1`, and read-only mode would otherwise stop there); a closed range stops where the data does for both kinds (no phantom blank rows past a CSV's end). The effective range comes back as `cell_range`.
- **Values** (`_xlsx_cell_text`): `None` → `""`; bool → `TRUE`/`FALSE`; int as is; a float at Excel's own 15-significant-digit precision without exponent or `.0` (`_num_text`: `1234.4999999999998` → `1234.5`, `0.1+0.2` → `0.3`, `7.0` → `7`); a number formatted purely `0…0` zero-pads to that width (the one format that changes *what* a value is — IDs/ZIPs); dates `YYYY-MM-DD` (datetimes with a time add `HH:MM:SS`) or `date_format` (strftime, validated up front). Other display formats (currency, %, thousands) are deliberately NOT rendered. CSV text passes exactly as written. A cell holding an Excel error (`#N/A`, `#REF!`, `#DIV/0!`, … — openpyxl's `data_type == 'e'`, or that exact text in a CSV) that the batch would read **refuses the whole batch**, by row and column; one in a row already skipped as done doesn't.
- **Privacy.** Cell values are client data: no response or error carries one — errors name rows, columns, headers and error codes only — except the explicit `dry_run` preview, which still goes through `_guard`'s path normalization. `test_batch_source_dry_run_launches_nothing_and_hides_values_otherwise` asserts a sentinel value never appears in a real run's reply.
- **The reply**: `source_kind`, `sheet` or `encoding`/`delimiter`, `cell_range`, `header_row`, `columns` (label → `{column, header}`), `skip_if_filled` (letters), `source_rows` (data rows read), `passes`, `pass_rows` (compressed source-row list, e.g. `4-9, 12`), `skipped` (`already_done` / `blank` / `required_blank` → count + rows), `source_modified` (mtime — plus `open_in_excel` when Excel's `~$` lock file sits beside it: the last SAVED version is what was read), `results_land`, and **`next_cell_range` + `resume_with`**: the range after the last row read (open-ended once a closed range is used up; a closed range whose data ended early resumes at its unread remainder, e.g. `A10:C20`), or — when a waited run stopped partway (`run.passes_done`) — starting at the first pass that didn't finish; `resume_with` is a ready argument set (`header=False`, columns as `col:X`, the same skip options and `date_format`) because a resumed range starts below the header. A dry run launches nothing, writes no batch file, and isn't refused by a running loop (its note says a real run would be).
- **Where results land.** The workflow's own `workflows\<Base>.inputs.csv` as `source` passes straight through as LoopRunner's batch file (no copy, handed over in its canonical spelling), keeping `fromSheet` — which the loop decides by comparing **full** paths (`WfLoopIsOwnSheet`, `GetFullPathNameW`): LoopRunner spells the sheet `<root>\lib\..\workflows\…`, so the plain string compare it replaced never matched and write-back silently became an append of every row (found in review; pinned by `batchrows.ahk /ownsheet`): collected values are filled in beside each row (`<Base>.results.csv` if the sheet is locked). It refuses every mapping/filter option (they'd break the record mapping) and an ANSI-saved sheet (the loop reads its own sheet as UTF-8). Every other source takes the `src = 0` route: results append to the inputs sheet as new rows (inputs used + values collected). The source file is never written.
- **Known limits, documented rather than guessed at**: rows hidden by an Excel filter are read (read-only mode can't see row visibility; use `require`/`skip_if_filled`/a range), a formula Excel never calculated reads as blank (and is reported as a skip, by row), numbers already stored as numbers have lost their leading zeros unless formatted `00000`, and `.xls` is refused. **Not built**: `run_workflow_batch(files=[...])` (one pass per file as `{{selected_file}}`) — the selection is a per-RUN snapshot (`wfSelection`, taken once for a whole loop) and a batch row only seeds ask labels, so per-pass files need an engine change; a workflow can take the path as an ask label (`{{File}}`) today.

**Processes: one primitive, an honest cap, background jobs** (2026-10-01, from a session that drove VoiceKit through a remote bridge whose per-call limit is 60 s — feedback items 1, 2 and 7). `run_ahk_snippet` accepted `timeout_s` up to 120, the bridge gave up at 60, and the snippet — with the python it had started through `cmd /c` — ran on unseen, holding its log file open, so every later run wrote an empty log (`subprocess.run(timeout=)` only ever killed AutoHotkey; its grandchildren were orphaned). All in `voicekit_writer.py`, thin wrappers in `server.py`:
- **`_ProcTree`** — the one child-process primitive for every BOUNDED run (`run_ahk_snippet`, `run_process`, the UIA probe behind `inspect_focus`/`dump_uia_tree`): the child is created `CREATE_SUSPENDED | CREATE_NO_WINDOW`, put in a fresh Windows job object (ctypes: `CreateJobObjectW`, `SetInformationJobObject` with `JOBOBJECT_EXTENDED_LIMIT_INFORMATION`, `AssignProcessToJobObject`), then resumed with `NtResumeProcess` (Popen has already closed the main thread's handle) — so nothing it starts escapes in the gap (measured: `cmd /c ping` lands cmd, its console host and ping in the job). `kill()` = `TerminateJobObject`, reporting `[{pid, image}]` read from `JobObjectBasicProcessIdList` first (conhost.exe left out of reports — Windows attaches one to every console child); if the job APIs fail the tree still runs and `kill()` falls back to `taskkill /T`. Bounded trees are `KILL_ON_JOB_CLOSE` (a dying server takes them along); `release(keep_running=True)` clears the flag first. All three std handles are always given (DEVNULL when unused): an inherited stdout would be the MCP protocol pipe — which is also why `_launch_and_report` redirects none (redirecting one makes Popen hand the child the server's other two). `_run_bounded` writes stdout/stderr to FILES (no pipe a grandchild can hold open), kills the whole tree on timeout or cancel, and after a normal exit either kills what was left (`run_process`: a foreground run owns its tree) or leaves it and reports `left_running` (`run_ahk_snippet`: a snippet may `Run()` an app on purpose). **What the job can't hold**: a process the tree did not CREATE — an out-of-process COM server it drives (`Excel.Application` from win32com, `New-Object -ComObject`, AutoHotkey's `ComObject()`: EXCEL.EXE `/automation -Embedding` is started by the DcomLaunch svchost — measured, its parent is svchost) or an app an already-running instance takes work from through the shell/DDE. A timeout can't end those, and they can keep a workbook locked — feedback #2's symptom. So after a timeout `_run_bounded` runs one scan, `_com_strays`: processes with `-Embedding` / `/automation` on the command line created since the run started, not already killed, reported as **`possibly_left_running`** (never killed — one started in the same seconds may be the user's) with a note naming `list_processes` and `taskkill`.
- **Cancellation reaches the processes.** `CURRENT_REQUEST` (a contextvar) holds `(id(session), request id)`; `server._guard` sets it from the FastMCP context (`get_context().request_context` — FastMCP runs sync tools through `anyio.to_thread.run_sync`, which carries contextvars into the worker; `None` outside a request, so the writer stays importable and usable without fastmcp). Every bounded tree registers under it; `_install_quiet_cancel`'s patched `cancel` calls `vk.kill_request((id(self._session), str(self.request_id)))` — the same pair — which `TerminateJobObject`s without waiting (it runs on the event loop). Pinned on the wire by `test_cancel_ends_the_request_tree_on_the_wire`. **A cancel can land before the tree exists** (the tool's thread is still expanding tokens, pruning run folders, in Popen): `kill_request` also records the request in `_CANCELLED`; `_run_bounded` starts nothing for a request already there, and `_track` ends a tree that registers after the cancel; `server._guard`'s `finally` calls `vk.request_done` (entries also expire after `CANCELLED_KEEP_S`). Review finding — the window is milliseconds wide, but the run then went its full timeout; pinned by `test_a_cancel_before_the_tree_exists_still_ends_it`.
- **The honest cap**: `max_wait_s()` — `MAX_WAIT_S = 50` (a remote bridge gives up at 60) unless `[MCP] MaxWaitSeconds` in `logs\settings.ini` says otherwise (clamped 5..230; read like `[Privacy]`: mtime-cached, UTF-16 or UTF-8, caseless). It replaces every scattered 120 (`WAIT_CAP_SECONDS` is gone): `run_ahk_snippet` / `run_process` `timeout_s`, `run_automation` / `run_workflow_batch` `wait_seconds`, `stop_job` `grace_s`, and `stop_module` `grace_s` (which had kept its own clamp at 60 — alone already past the bridge — until review). `_cap_wait` clamps and returns the note the reply carries (`timeout_capped`, `wait_capped`, `grace_capped`) — a clamp is never silent; `reserve=` caps the wait lower by what the call spends around it (`stop_module`: `STOP_KILL_WAIT_S` + `STOP_SCAN_RESERVE_S`), so the whole call fits. A foreground `timeout_s` goes through `_cap_timeout`: 0 means "up to the cap" (it used to become a 1-second kill, while a background job's 0 means no limit). Not capped, and said so in the README: a create/update that reloads VoiceKit (its validates and `LAUNCHER_WAIT_S` have their own bounds). The parameter descriptions state the cap the server started with; the session instructions carry one line on it.
- **The user's automations are NOT in a job**: `run_automation`, `press_hotkey`, loops and batches launch the way a voice shortcut does and must outlive the server and any cancelled request. A waited `run_automation` that times out keeps running as before, and now says which processes (`still_running`, from one process scan walking the parent links, `_tree_of`).
- **`run_process(exe, args, cwd, timeout_s, stdin, env, background, unmask)`** — no shell: `exe` is a full path or a bare name found by `shutil.which` (PATHEXT included, so `npm` finds `npm.cmd` and is refused); only `.exe`/`.com` run — `.bat`/`.cmd` are refused with the explicit `cmd.exe /d /c` form (BatBadBut: batch arguments go through cmd's own parsing, so they can't be passed safely for the caller), `.ps1` with `powershell -File`, `.py` with the interpreter form. `exe`/`args`/`cwd`/`env` values go through `expand_user_paths` (tokens and `%USERPROFILE%`/`%TEMP%`); `args` reuse `_run_args(line_breaks=True)`: NUL refused; a line break is allowed (CreateProcess with a `list2cmdline`-quoted argument hands `\r`/`\n` back intact — measured: `python -c` with three lines, `'q"\r\nz'`) except for `cmd.exe`, which stops reading at the first one (`run_automation` keeps its old refusal). `env` merges over the server's environment caseless (null removes), values never echoed; `PYTHONIOENCODING=utf-8` and `PYTHONUNBUFFERED=1` unless the server's environment sets them or the caller's `env` names them (even to remove) — a file stdout is block-buffered, so a running job's tail stayed empty and a timed-out run lost what it printed. Output decoding (`_pick_codec`): UTF-16 (BOM or the NUL-every-other-byte shape), else UTF-8, else a caller-given `fallback` (AutoHotkey output: the ANSI code page, `_ansi_codec` — `FileAppend(x, "*")` with no encoding writes CP0, and the OEM fallback turned `café —` into `cafΘ ù`), else the console OEM code page, else cp1252; CRLF → LF; each stream capped at `OUTPUT_CAP_BYTES` (100 KB: first and last 50 KB around `... N bytes omitted ...`, split UTF-8 characters at the cut dropped). Foreground cwd defaults to `%TEMP%`. `unmask` is the scoped privacy opt-out (see **reveal / unmask** above), passed to `_guard` exactly like `run_ahk_snippet`'s and `read_job`'s.
- **Background jobs** (a VoiceKit "job" — not the Windows job object it runs in): `run_process(background=True)` returns `job_id` (`jYYYYMMDD-HHMMSS-xxxx`) at once; output goes to `%TEMP%\VoiceKit\jobs\<id>\` (`stdout.txt`, `stderr.txt`, `meta.json` with pid + process creation time, and `exit.json` once it ends; `JOBS_ROOT` retargets it for tests). Not kill-on-close, and started with `CREATE_BREAKAWAY_FROM_JOB` when the server's own job allows it (a client that runs its MCP server in a kill-on-close job would otherwise take every background job with it), so a job survives a server restart. `timeout_s` is a lifetime (default `JOB_DEFAULT_LIFETIME_S` = 3600 s, 0 = none, max 7 days) enforced by a watcher thread on the whole tree — leftovers that outlive the main process included. `read_job` (no id = the list) reports state (running / exited / killed / stopped), exit code, duration, output tails and `still_running` leftovers; `stop_job` ends the tree via the job object and names what it killed. After a restart the job handle is gone (a named job object does NOT outlive its creator's handle — measured), so a still-running job is identified by pid + creation time and ended with `taskkill /T`, and its exit code is reported as unknown. Pruned on start/list: finished folders older than 7 days, and never more than 50 kept. `meta.json` keeps the FULL `exe` path (so the reply's path pass masks a program inside a client folder) and the privacy **tokens** the job's exe/args/cwd/env carried — never the names.
- **Names that came in as tokens stay masked in later calls** (review finding). The bare-name pass masks a name shown without its path only when the same answer shows the path or the current call expanded it (`privacy.take_expanded`); a background job handed `<file#..>.pdf` that printed the bare name, and `list_processes`' command lines, came back in clear. Every launch now remembers its input tokens (`_input_tokens`): a job in `meta.json`, a bounded run on its tree (`_ProcTree.tokens`), a `run_automation` launch (and a snippet's kept leftovers) in `_LAUNCH_TOKENS` by pid. `read_job` / `stop_job` re-expand the job's, `list_processes` every one it knows (`_recall_tokens` → `privacy.expand_tokens`, which notes them into this call's `known`). Over-masking an unrelated row is the safe direction. Limit: a `run_automation` launch from before a server restart is not remembered (a job is).
- **`list_processes(name, include_command_line, max_rows)`** — one `_cim_processes()` query (which `_ahk_processes` and `_python_processes` now filter too; output forced to UTF-8 so an accented name in a command line survives) with a `voicekit` tag on VoiceKit's own: this MCP server (and its venv launcher), other server instances, the master / launcher / watchdog, `module body <name>`, `macro <name>`, `loop <name>`, the UIA probe, `snippet`, `run_process`, `job <id>`, and otherwise anything this server started. Tagged rows first; command lines capped at 2000 characters; everything through `_guard` like every response.

The non-test waited run is still not in a job: a timeout leaves it running (`still_running`).
- **`test=True`** launches `[AHK_EXE, "/ErrorStdOut=UTF-8", "/include", lib\TestShim.ahk, <macro>, *args]` through **`_run_bounded`** (the WP1 primitive — job object, request-scoped cancel, `max_wait_s()` cap) with `VOICEKIT_TEST=1`, `VOICEKIT_TEST_LOG`, `VOICEKIT_RESULT_FILE` and `VOICEKIT_RUN_SCRIPT`. ## The lockstep lists

The five-way step-type list and the mirrored-pairs list are rules, so they stay
in `CLAUDE.md` ("Lockstep lists"). The full writer-mirror paragraph they came

`mcp\voicekit_writer.py` is a **deliberate second implementation** of the AHK write-side (`CleanPhrase`, `WfEncode`, `AhkStrLit`/the "Open Something" generator incl. its `;  Opens:` header line that Home parses, the `ai-template` fill + `prompts\` files, the bridge allocator, the stub/steps formats, **SpaceOut-named `.lnk` creation** and phrase-collision checks, the snippet brace/semicolon/duplicate guards, reload). Deletion protects VoiceKit's own tools **case-insensitively** (`_BUILTINS_LOWER` — spoken "Ask AI" cleans to base `AskAi`, and NTFS would match `AskAI.ahk`). This duplicates format knowledge that otherwise lives only in AHK — the tradeoff was accepted because `mcp\test_conformance.py` mechanically enforces parity: it feeds the writer's output through the **real** engine (`lib\Workflow.ahk` `WorkflowLoad`) and byte-compares, runs every mirrored generator on both sides (`test_generators_match_ahk` — the Studio's stub text lives in `WfStubContent` in `Workflow.ahk` so the test exercises the real thing), and covers the AI-action/opens/guard behaviors. **If you change any on-disk format (encoding, stub text, the `Generated by Workflow Studio` marker, file naming, BOM/LF), update `voicekit_writer.py` in lockstep and re-run the conformance test.** Newly created files are UTF-8 **with BOM** and **LF** endings (matching AHK `FileOpen`); the writer reproduces that exactly. Step-type coverage is a **five-way** lockstep. All five must list the same types, or a type the engine supports becomes unreachable somewhere (this bit `if`/`else`/`endif` until the MCP schema was extended, and `set` touched all five).
