# Resilience — surviving a bad module, a crash, a sleep

> history and design notes live here). "Above"/"below" may point into a sibling

> and "the traps section" / "the lockstep list" are in `CLAUDE.md` itself.

How the resident master stays up: the reload preflight and quarantine, the boot launcher, runtime error capture, the watchdog and safe mode, and health reporting.

**Surviving a bad module** (2026-07-31) — the master is ONE process holding every hotkey and every snippet, and `VoiceKit.ahk` pulls `hotkeys\_index.ahk` in at **compile** time. So a module that stops parsing means the master never starts at all, and before this it stayed dead until a human noticed. Three distinct failure modes, three distinct fixes — note that wrapping a module body in `try/catch` only addresses the mildest one:

- **Won't compile** → **`ReloadMasterNotify(root)` in `_Common.ahk` is the one reload chokepoint.** It `/validate`s `VoiceKit.ahk` first (`AhkValidate`, via a cmd redirect — see the traps section), and on failure **quarantines** the offending module by commenting out its `#Include` (`MasterErrorModule` finds it from the error text; `CommentOutLinesContaining` parks it, reusing the `;`-to-disable mechanism the manifest header already documents), then re-validates and reloads with everything else intact. Only `hotkeys\` modules are parkable — a broken `lib\` or `VoiceKit.ahk` leaves the running master alone rather than being disabled. Two special cases (2026-09-29): a module whose **file is missing** makes AutoHotkey blame the manifest (`...\hotkeys\_index.ahk (N) : ==> #Include file "...\hotkeys\Gone.ahk" cannot be opened.`), so `MasterErrorModule` returns the *missing* module (only when `_index.ahk` is the includer — never `_index.ahk` itself) and its line is parked with a "file is missing" note; and a check that **times out** (a `#Warn` warning — see the traps section) is retried once at twice the bound (a slow login or AV scan can time out too), and only a second timeout parks every active module carrying `#Warn` (`MasterWarnModules`). `voicekit_writer.master_preflight` mirrors both. **Every** reload goes through it (`^!+r`, `HotkeyCompanionRetire`, NewAutomation ×2, Home ×4, and Python `reload_voicekit`). `ReloadMasterNotify` shows the message *before* relaunching, because when the master calls it the new instance replaces this process the moment `RunAhk` returns.
- **Per-user files first** (2026-09-30) → `MasterPreflight`'s first step is `SeedUserFiles` (see "Per-user files" in `modules-and-bodies.md`): a fresh install has no live `hotkeys\_index.ahk` / `bridge-map.txt` / `hotkeys\Snippets.ahk` until it makes them from the shipped `*.default` copies, and an upgrade gets any newly shipped hotkey line added. `VoiceKit.ahk` includes the manifest as `#Include "*i ..."` and runs the same seed on start, reloading through `ReloadMasterNotify` if that changed the manifest (and then exiting at once — `ReloadMasterNotify(root, &launched)` says a replacement was started, and the old instance must not race it writing `installed.flag`, showing the welcome window or starting a watchdog; `MasterExit` is unhooked first so the hand-over never stamps `clean_exit` over the replacement's status) — so even a direct launch with the manifest missing comes up. Python `master_preflight` mirrors it (`seed_user_files`).
- **Won't compile at BOOT** → **`VoiceKitLauncher.ahk`** (repo root) does the same preflight before starting the master, and is what `Setup.bat`, `build\Install-VoiceKit.cmd` and the Startup `.lnk` target. `EnsureStartupViaLauncher` repoints older installs' shortcuts once. It includes **only** `_Common.ahk` (which includes nothing itself), so no user module can break the thing that rescues user modules.
- **Throws at runtime** → `OnError` in `VoiceKit.ahk` logs to `logs\errors.log`, records it in the status file, TrayTips, and returns 1 so no modal dialog is left sitting in front of the user.
- **Crashes hard** (an access violation from a bad `ComCall`/unpinned COM vtable — see the `Acc.ahk` trap; nothing in-process can catch it) → **`lib\Watchdog.ahk`**, started by the master. Liveness is the **heartbeat freshness** in `logs\master-status.ini` (written every 5 s), deliberately *not* a PID check — `#SingleInstance Force` kills the old PID on every normal reload, so a PID test would misfire constantly while a heartbeat only goes stale on a real death. A deliberate exit sets `clean_exit` (`MasterExit` filters on the OnExit reason: `Menu|Close|Exit|Logoff|Shutdown`, never `Reload`/`Single`) and the watchdog stops. **Crash-loop → safe mode**: 3 restarts inside 120 s parks every module and drops `logs\safe-mode.flag`. Restart stamps live **on disk** under `[Watchdog]`, not in memory, because the master relaunches the watchdog on every start — an in-memory counter reset each crash and safe mode never fired (measured: the log read "1 restart" three crashes running). Watchdog is `#SingleInstance **Ignore**` for the same reason. If safe mode has nothing left to park, it backs off for 10 minutes instead of restart-looping. **Sleep/resume is not a crash** (2026-09-29): on wake the watchdog's poll and the master's heartbeat come due together, and whichever ran first decided — a healthy master got "restarted" after most resumes (114 such lines in one `errors.log`). A poll arriving more than 3× `POLL_MS` after the last one (A_TickCount counts through sleep) now sets a grace-period hold instead — and holds only ever **extend** (`WatchdogHoldUntil`): a wake during the 10-minute back-off must not cut it to the 20 s grace and relaunch a master that is still crash-looping. The decisions are pure functions in `_Common.ahk` — `WatchdogDecide`, `WatchdogStampsInWindow`, `WatchdogRestartPlan`, `WatchdogHoldUntil` — so `preflight-selftest` drives every branch; they live there, not in `Watchdog.ahk`, because that file starts its poll timer the moment it is included.
- **Reporting** — `voicekit_writer.health()` (status file + `voicekit_running()` + `index_modules()`) is merged into **every** MCP tool response by `server._guard` — current state only: `last_error` only when `last_error_at >= started` (with `last_error_age_s`), `safe_mode` from the flag file alone, and a refused reload is forgotten once a master has started since — and the master TrayTips anything parked at startup (`ReportQuarantine`). The original complaint was as much about silence as about breakage.
