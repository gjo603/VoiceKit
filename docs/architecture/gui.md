New Automation (the scaffolder), the home window, the AI layer, `lib\_Common.ahk`, `lib\Theme.ahk`, and Split Pages.

**The scaffolder** — `macros\NewAutomation.ahk` ("open new automation") is **intent-first and no-code-first**: a themed chooser of six plain-language intents, every flow a themed dialog (no `InputBox`/`MsgBox` chains). (1) **Open Something** generates a launch macro from `VkOpensMacroContent` in `_Common.ahk` (a header + one `Run(...)` line via `AhkStrLit` — the string-literal escaper, now in `_Common.ahk` and escaping every `;` too (2026-09-30: a space-preceded `;` inside a string starts a comment, so a target or typed text containing ` ;` generated a file that couldn't load; `voicekit_writer.ahk_str_lit` mirrors it and `test_ahk_str_lit_matches_ahk` runs both); every GUI generator now `AhkValidate`s what it wrote (`AhkWriteChecked`/`HotkeyWriteChecked`) before a phrase or `_index.ahk` points at it; `templates\launch-template.ahk` remains for the MCP writer and as documented building blocks). (2) **Record My Steps** goes through `OpenStudioSafely` (`_Common.ahk`, shared with Home's Edit, Draft With AI and RecordMySteps via `StudioWindow()`), which **activates an existing Studio window instead of launching** (a raw launch's `#SingleInstance Force` would silently kill an open session) — and treats a *hidden* Studio (recording or testing) as busy, not absent (2026-09-30: three of the four hand-rolled checks missed it and relaunched over a live recording). (3) **Type Text For Me** = snippet (one dialog, **multi-line** edit box; `SnipEncode`/`SnipDecode` in `_Common.ahk` are the shared escape codec — `SnipEncode` escapes backticks AND semicolons (a bare `;` would start a comment in the hotstring line) then folds real newlines into `` `n `` so a multi-line snippet stays on its single on-disk line, mirroring `voicekit_writer.create_snippet` exactly; beside them `SnippetParseLine`/`SnippetExists`/`SnippetValidate`/`RemoveSnippetLine`/`ReplaceSnippetLine` are the one parser and rule set — an abbreviation may not hold `:` or a backtick — and `SnippetFileChange` load-checks every GUI edit of `Snippets.ahk` and puts the old bytes back if it no longer loads, since the preflight would otherwise park the whole file). (4) **AI Text Action** and (5) **Draft With AI** are the AI layer (below). (6) **Always-On Hotkey** offers no-code actions (open/type, generated inline) with "custom code" as the escape hatch — that path now goes through `HotkeyIsolatedCreate` (launcher + out-of-process body, and Notepad opens the **body**; see "Isolated module bodies" above; `templates\hotkey-template.ahk` remains for the MCP writer's `isolate=False` placeholder); key allocation/`_index.ahk`/`bridge-map.txt`/reload unchanged, ending in a themed pairing-instructions dialog.

**The home window** — `macros\VoiceKitHome.ahk` ("open voice kit") lists every automation (workflows + their loop phrase, macros, AI actions, hotkey modules from `bridge-map.txt`, snippets parsed from `Snippets.ahk`, VoiceKit's own tools last) in a searchable ListView with Run / Edit / Hotkey / Delete / New Automation / AI Settings. Run for a hotkey row does `SendLevel(1)` + `Send` of the combo so hook hotkeys hear it. Edit for a workflow launches the Studio with the steps file as its argument via `OpenStudioSafely` (see Studio args below; an open Studio is activated instead, a busy one left alone); Edit for a snippet opens an in-place editor (`EditSnippetDialog`: abbreviation + multi-line text, decoded with `SnipDecode`, rewritten with `ReplaceSnippetLine`, which preserves the line's position, its `:*:`/`::` options, and any comment above it — dynamic code-block snippets still open in Notepad); Delete removes *all* artifacts of an automation through `_Common.ahk`'s shared recipes (`DeleteWorkflowArtifacts`, `DeleteMacroArtifacts`, `DeleteHotkeyModuleArtifacts` — the last also takes the body, `logs\module-backups\<Base>.prev.ahk`, the body-status line and stop flag, matching MCP `delete_automation`; macro/AI deletes take `logs\macro-backups\` too; hotkey deletes reload the master; tools can't be deleted, and neither can Split Pages, which stays editable — `VkBuiltinTools`/`VkEditableTools`/`VkDeleteProtected` are the one AHK list, compared against the writer's `_BUILTINS`/`_DELETE_PROTECTED_LOWER` by `test_builtin_tools_match_ahk`). Its dialogs show through `ThemeShowModal`. Its Start Menu entry is special-cased to **`Voice Kit.lnk`** (so the phrase is "open voice kit", not "open voice kit home") — both in `VoiceKit.ahk`'s first-run loop and in the window's own self-heal; this is the one exception to the SpaceOut naming convention. `macros\VoiceKitHelp.ahk` is now a thin alias that launches Home (keeps the old "open voice kit help" phrase working).

**The AI layer** (optional, opt-in — the deliberate exception to "no cloud calls") — `lib\AI.ahk` (OpenRouter chat-completions over `WinHttpRequest`, DPAPI-encrypted key + model in `logs\settings.ini` `[AI]`, `AISettingsDialog`, `AIComplete(system, user, &err)`, `AIGrabInput` clipboard-preserving selection grab) on top of `lib\Json.ahk` (minimal strict JSON parse/escape; objects→Map, arrays→Array, null→""). **Include order matters**: hosts must `#Include` `_Common.ahk` + `Theme.ahk` *before* `AI.ahk` (which includes `Json.ahk` itself). Nothing calls the network until a key is saved; the engine (`lib\Workflow.ahk`) has no AI knowledge. Three surfaces: **`macros\AskAI.ahk`** ("open ask ai" — Wispr-style bottom-center pill; answer is typed into the previously active window, else shown with Copy); **AI text actions** (`templates\ai-template.ahk` filled with `{{PHRASE}}/{{BASE}}/{{DATE}}`; the prompt lives in `prompts\<Base>.prompt.txt` so no code-escaping of user prompts is needed, and Home edits it in place); **Draft With AI** (New Automation: description → strict-JSON steps → `ParseDraft` validates types/if-conds/balance → writes `logs\ai-draft.steps.txt` via `WfEncode` → opens the Studio on it). **If step types ever change, `DraftSystemPrompt` + `ParseDraft` in NewAutomation.ahk are part of the five-way lockstep** listed in the MCP section below. A type can be handled by REFUSING it: `capture` (a shell command) is rejected by name with a pointer to the Studio, and the prompt tells the model never to emit one. `ParseDraftInner` keeps paramC only for the types with their own branch (`if`, `waitfor`, `drag`, the pointer steps) and blanks it for the explicit `paramCless` list; any other type is refused — the old "blank paramC for everything else" catch-all would have silently eaten a new paramC type's value.

`lib\_Common.ahk` holds shared helpers (`EnsureDir`, `Notify`, `RunOrActivate`, `CleanPhrase`, `Log`, plus `RunAhk`/`MakeAhkShortcut`/`IsReservedName` — the last three make launching/shortcuts association-proof by targeting `A_AhkPath` with the script as an argument). Standalone macros include it via `#Include "%A_ScriptDir%\..\lib\_Common.ahk"`. Two additions from the 2026-08-05 feedback round: **`RobustMove(src, dst, timeoutMs := 1200, overwrite := false)`** — the "move a file an app just touched" race as one primitive (a rename is blocked by ANY open handle without delete-sharing, so it retries, then falls back to `FileCopy` — a read lock blocks renaming, not reading — returning `"moved"` / `"copied"` / `""`, never throwing; on `"copied"` the source is left for the caller's cleanup; Split Pages' `SavePage` delegates to it now); and **uncaught-error capture** — `_Common.ahk`'s one piece of top-level auto-execute code, `OnError(LogUncaughtError)`, registers during the include so EVERY host (macros, bodies, the Studio, the master) appends uncaught errors to `logs\errors.log` (stamp | script name | message [file line N]) before stock handling proceeds (it returns 0: dialogs still show, later handlers still run). `VoiceKit.ahk`'s `MasterError` runs second, reuses `ErrorLogLine`, and no longer writes its own duplicate log line; the snippet prelude registers its own handler with `AddRemove=-1` so probe errors exit through their report channel BEFORE this logger can put them in the user's error history. **Both logs are capped** (2026-09-30): `LogTrimIfOver` (1 MB, `LogCapBytes`) drops the oldest half at a line boundary before `Log`/`ErrorLogAppend` append — the engine's `WfLogTrim` rule for `workflow-runs.log`, kept as a separate copy because the engine includes no `_Common`; Python's `log()` (the other `created.log` writer) mirrors it in `_log_trim_if_over`, and `test_log_cap_matches_ahk` compares the two. A trim is **crash-safe**: the kept half is written to `<log>.tmp-<pid>` and moved over the log (`FileReplaceText` in `_Common.ahk`, `_replace_text` in Python, the engine's own copy in `WfLogTrim`) — it used to be delete-then-append, so a process killed between the two lost the whole log; a move refused because another writer holds the log leaves it untouched and over the cap until the next append. The read side is MCP `read_log("errors")`.

`lib\Theme.ahk` gives every GUI one modern look: it follows the Windows light/dark setting (`AppsUseLightTheme`), sets a matching title bar (DWM `DWMWA_USE_IMMERSIVE_DARK_MODE`), rounds corners (`ThemeRound`, DWM attribute 33 — matters for the caption-less floating bars), and dark-themes the **native** controls (`SetPreferredAppMode` ordinal 135 + `SetWindowTheme`, plus a `WM_CTLCOLOR*` hook for edit backgrounds). Call `ThemeApply(gui [, statusTextCtrl])` right before `Gui.Show()` — or, for a modal dialog, `ThemeShowModal(d, owner, dims, focusCtrl, showOpts, statusCtrl)`, the one copy of the theme/dim/show/disable-owner/wait tail (it reads every hwnd before `Show` and re-enables the owner in a `finally`; `showOpts` may be a placement function like `ShowBottomRight`, and a function in `dims` runs after theming); `ThemePalette()` returns the colors; `ThemeDim(ctrl)` colors a hint/caption; `ShowBottomLeft`/`ShowBottomCenter`/`ShowBottomRight` place floating pills in the work area (each reads the Gui's HWND once, before any `Show`, and passes it bare so the still-hidden window is found — the dialog-lifetime trap) (center activates — it's for input bars like Ask AI). `VoiceKit.ahk` itself includes Theme now, for the first-run **welcome window** (Voice Access running-check with a turn-on button + live timer, start-at-login checkbox, "try saying" teach line — replaces the old MsgBox chain; the installed.flag is written *before* the welcome shows). **Keep controls native — never swap buttons for owner-drawn/custom widgets** — because Voice Access clicks a button by its accessible name (its caption); a custom widget has none. Button captions may carry a leading **monochrome, text-presentation** glyph (e.g. `●▶✕＋✎↑↓`, and `🖫` U+1F5AB for Save) but must keep the real word so voice matching still works; avoid emoji-presentation glyphs (`🗑💾⏺`) — they render in color and clash. Studio, New Automation, Home, Ask AI, AI Settings and the welcome window all call `ThemeApply` (Help is now a GUI-less alias).

**Split Pages** (`macros\SplitPages.ahk` + `lib\split_pdf.py`) — a hand-written tool macro ("open split pages"): takes the PDF selected in File Explorer (`ExplorerSelectedFiles()` from `lib\ExplorerSel.ahk`: the active tab of the topmost `CabinetWClass` window with a selection — the old inline copy could read a background Windows 11 tab; several files selected is refused rather than guessed), splits it per page through the python helper (pypdf; a missing pypdf is a consented one-time `pip install`, recognized by the helper printing `NEEDS_PYPDF`), then cycles: preview in the default viewer → themed dialog for a short description → saved beside the original as `<yyyy-MM-dd> <description>.pdf` (collisions get ` (2)`; blank description falls back to `Page <n>`; Skip discards the page, Stop aborts the rest; the original is never touched). **Saving is lock-tolerant** (2026-07-27, after field failures at line `FileMove`): the viewer can hold the temp page past its window's close, and a rename is blocked by ANY open handle without delete-sharing — so `SavePage` retries ~1.2 s and then falls back to `FileCopy` (a read lock blocks renaming, not reading; the temp original is left for the end-of-run cleanup), with a voice-clickable Try Again / Skip dialog only if both fail; `ClosePreview` waits up to 2 s for the viewer window to really vanish (WinClose only posts); and each run splits into a unique `%TEMP%\VoiceKitSplit\run <A_Now>` subfolder so a still-locked leftover from a previous run can never collide. The retry-then-copy dance was hoisted to `_Common.ahk` **`RobustMove`** (2026-08-05 feedback — the race belongs to every "move a file an app just touched" flow, and hand-written macros doing the same dance can now call one primitive); `SavePage` is a one-line delegate. Same round: **`SplitPdf` reads the page count from the LAST integer-only line** of the helper's output (`LastIntLine`), not `IsInteger()` on the whole merged blob — `RunCapture` folds stderr in with `2>&1`, so one pypdf warning used to turn a successful split into an error dialog (and buffering means the warning can land before OR after the count). Test hook: `SplitPages.ahk <file.pdf> nopreview` bypasses Explorer lookup and the viewer.
