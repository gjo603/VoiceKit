How `build\` packages VoiceKit, what ships and what never does, how the installer upgrades an existing install, and the repo's line-ending policy.

**Distribution** — committed tooling lives in **`build\`**; outputs go to **`dist\`** (gitignored). Run `build\Build-Installer.cmd` (double-click) or `build\Build-Installer.ps1 [-Exe]`: it stages **git-tracked files plus uncommitted edits to them** (`git stash create` + `git archive`, then filtered to exactly what `git ls-files` lists (run with `-c core.quotepath=off` and read as UTF-8: by default git prints a non-ASCII path as a quoted octal escape that matches no staged file, silently dropping it from the package) — the stash snapshots the working tree of every path HEAD knows, so a file just untracked with `git rm --cached` still rode along until the next commit; untracked personal automations never leak into a package, so **commit new source files before building**; a must-ship sanity list aborts the build if a core file is missing — the three `*.default` files and the RecordMySteps companion included), drops the dev-only files (`build`, `CLAUDE.md`, `Setup.bat`, `.gitignore`, `.gitattributes`, `docs`, `tests`), never ships a live per-user file (`hotkeys\_index.ahk`, `bridge-map.txt`, `hotkeys\Snippets.ahk` — only their defaults; see "Per-user files" in `modules-and-bodies.md`), **load-checks the staged `VoiceKit.ahk`** against live files seeded from the staged defaults (through a `cmd.exe` redirect, bounded; the seeded copies are removed again) and aborts on failure — a build from a working tree whose manifest listed unshipped modules used to produce a master that never started — bundles a portable `AutoHotkey64.exe` (so the tester needs no winget/AHK), adds `build\Install-VoiceKit.cmd`, and zips `dist\VoiceKit-Setup.zip`. `logs\` (which holds the DPAPI-wrapped OpenRouter key in `settings.ini`) and `prompts\` are gitignored, so they can neither be committed nor shipped. `Install-VoiceKit.cmd` robocopies to `%LOCALAPPDATA%\Programs\VoiceKit` and launches via the bundled interpreter (so `A_AhkPath`, and thus every generated macro/loop shortcut, uses the bundle). The copy is additive (`robocopy /E`, never `/MIR`/`/PURGE`) and excludes the three live per-user file names outright, so an upgrade can never overwrite or remove the user's registry, manifest or snippets — new shipped hotkeys reach them through `SeedUserFiles` on first start instead. Production-review hardening baked into `build\Install-VoiceKit.cmd`: **excludes `Setup.bat`** (a wrong-file click would do a fragile in-place install pointing shortcuts at a temp folder), **`Unblock-File`s the target** to strip Mark-of-the-Web (the unsigned bundled exe would otherwise trip a security prompt; cancel = silent no-op install), and **scopes the pre-copy `taskkill`** to AutoHotkey processes whose path is under the target (a blanket `/im` would kill unrelated AHK scripts, but a `VoiceKit.ahk`-only filter would miss a running loop/Studio holding the file lock). `-Exe` wraps the zip into a self-extracting `.exe` via IExpress (`bootstrap.cmd` → delegates to the same installer) — IExpress needs an interactive desktop, so it no-ops headless.

**Version stamp** (2026-09-30) — the repo carries a root `VERSION` file (`1.2.0`; bump it on a release). The build writes `<base>+<short hash>[.dirty].<yyyyMMdd>` into the **staged** copy after the index filter (so it ships even before `VERSION` is committed) and lists it in the must-ship check. The MCP server reports it (`health().version`, `server_info`, FastMCP serverInfo) — an installed copy has no `.git`, so this file is the only way to tell which build an installed copy is running.

**Line endings** (2026-09-30) — `.gitattributes` used to force CRLF on checkout (`* text=auto eol=crlf`) while every generator — AHK and the Python writer — writes LF, so user-mutated files ended up mixed and every git command warned. Now source and data are LF (`*.ahk *.txt *.py *.md text eol=lf`) and only the Windows scripts are CRLF (`*.bat *.cmd *.ps1 text eol=crlf` — cmd.exe can misparse labels in an LF batch file). The index was already all-LF, so the switch changed no stored content; an existing checkout keeps its CRLF working copies until files are next checked out, which nothing depends on (byte-compare tests normalize, and `_read_template` / the AHK template fills preserve whatever the template has on disk).
